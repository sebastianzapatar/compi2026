Arquitectura

El Pipeline del Intérprete

El intérprete transforma el código fuente en 4 etapas secuenciales. Cada módulo tiene una responsabilidad única.

1

Lexer (Análisis Léxico)

Lee el código carácter por carácter y lo convierte en una secuencia de tokens significativos.

2

Parser (Análisis Sintáctico)

Consume los tokens y construye un Árbol Sintáctico Abstracto (AST) usando un Pratt Parser.

3

Evaluador (Ejecución)

Recorre el AST nodo por nodo y ejecuta el programa usando un tree-walking interpreter.

4

Object System (Valores)

Sistema de objetos que representa todos los valores en tiempo de ejecución: enteros, strings, funciones, etc.

Reflexión

¿Por qué un Tree-Walking Interpreter?

Aunque es la aproximación más sencilla, es extremadamente útil y sus fundamentos son los mismos que usan los compiladores más avanzados del mundo.

"Si puedes construir un intérprete, puedes entender cualquier compilador. Las fases son las mismas: lexing, parsing, análisis semántico, evaluación. Solo cambia qué haces con el AST al final." — Robert Nystrom, autor de Crafting Interpreters

🎓 Valor Educativo Incomparable

  • 🔍 Se ven TODAS las fases del compilador: léxica, sintáctica, semántica y ejecución
  • 🧩 Cada módulo es pequeño y comprensible — no hay "magia" oculta
  • 🐞 Debugging sencillo: se puede inspeccionar cada token, nodo y valor
  • 📚 Los conceptos (precedencia, scoping, closures) son universales y aplican a todo lenguaje

🏭 Uso Real en la Industria

  • ⚙️ Configuración y DSLs: Terraform (HCL), Nginx, YAML processors, Dockerfile
  • 🔬 Prototipado rápido: Probar nuevas ideas de lenguaje antes de optimizar
  • 🛡️ Linting & Formateo: ESLint, Prettier, Black — todos construyen un AST y lo recorren
  • 📊 Consultas / Filtros: jq, GraphQL, SQL parsers

El Parser consume tokens y construye un Árbol Sintáctico Abstracto (AST). Usamos un Pratt Parser para manejar las precedencias de operadores.

🧠 Conceptos Clave del Pratt Parser

nud Null Denotation — parsea tokens al INICIO de una expresión (números, identificadores, paréntesis abierto)
led Left Denotation — parsea tokens en posición INFIJA (operadores binarios como +, *, ==)
Ejemplo: 1 + 2 * 3 // El parser respeta las precedencias: // * tiene mayor prioridad que + InfixExpression ┌─────┼─────┐ 1 + InfixExpression ┌─────┼─────┐ 2 * 3 // Resultado: (1 + (2 * 3)) = 7

Fase 4 — ast.py

Árbol Sintáctico Abstracto (AST)

El AST es la representación intermedia del programa. Cada construcción del lenguaje es un nodo en el árbol.

📂 Sentencias (Statements)

No producen un valor. Ejecutan una acción.

  • P Program — nodo raíz del programa
  • L LetStatement — let x = expr;
  • R ReturnStatement — return expr;
  • E ExpressionStatement — expr;
  • B BlockStatement — { ... }
  • W WhileStatement — while (...) { }
  • F ForStatement — for (...;...;...) { }

📐 Expresiones (Expressions)

Producen un valor al evaluarse.

  • I Identifier — nombre de variable
  • N IntegerLiteral / FloatLiteral
  • S StringLiteral / BooleanLiteral
  • P PrefixExpression — !x, -5
  • I InfixExpression — a + b
  • C IfExpression — if/elseif/else
  • F FunctionLiteral / CallExpression
AST Visual // let resultado = 10 + 5; LetStatement ├── name: Identifier("resultado") └── value: InfixExpression ├── left: IntegerLiteral(10) ├── operator: "+" └── right: IntegerLiteral(5)
🌳
Evaluador — Parte 1

¿Qué significa "Tree-Walking"?

"Caminar el árbol" significa visitar cada nodo del AST desde la raíz hasta las hojas, y ejecutar la acción de cada nodo. Es como leer un árbol genealógico de arriba a abajo.

📝 Código fuente:

let x = 3 + 5 * 2;

🌲 AST generado por el Parser:

LetStatement ← ❶ empezamos aquí ├── name: "x" └── value: InfixExpr ← ❷ evaluar valor ├── left: IntegerLiteral(3) ← ❸ ├── op: "+" └── right: InfixExpr ← ❹ ├── left: IntegerLiteral(5) ← ❺ ├── op: "*" └── right: IntegerLiteral(2) ← ❻

⚡ Paso a paso del Evaluador:

❶ Veo un LetStatement. Necesito evaluar el valor del lado derecho y guardarlo.
❷ El valor es InfixExpr(+). Necesito evaluar izquierda y derecha primero.
❸ Izquierda es IntegerLiteral(3) → retorno Integer(3)
❹❺❻ Derecha es InfixExpr(*): evalúo 5 y 2 → Integer(10)
❷✓ Ahora sumo: 3 + 10 → Integer(13)
❶✓ Guardo en Environment: x → Integer(13) ✅
📦
Evaluador — Parte 2

El Environment: ¿Dónde se guardan los valores?

El Environment es simplemente un diccionario (tabla clave→valor) que guarda las variables. Pero tiene un superpoder: puede encadenarse con un entorno padre.

📋 ¿Qué es un Environment?

Es un objeto con solo 2 atributos:

class Environment: _store: Dict[str, Object] # {"x": Integer(10), "nombre": String("Laura")} _outer: Optional[Environment] # Referencia al entorno PADRE (None si es global)

🔍 ¿Cómo busca una variable? → env.get("x")

1. Busca "x" en su propio _store
2. Si NO la encuentra → pregunta al _outer (entorno padre)
3. El padre busca en SU _store, y si no, en SU _outer...
4. Si llega al global y no está → Error: "variable no definida"

🎯 Ejemplo visual con código:

let x = 10; let y = 20; let suma = function(a, b) { return a + b; }; print(suma(x, y)); // 30
Entorno Global (_outer: null)
"x"   → Integer(10)
"y"   → Integer(20)
"suma" → Function(params:[a,b], body:..., env:👆)
↑ _outer apunta aquí
Entorno de suma(10, 20)
"a" → Integer(10) ← parámetro
"b" → Integer(20) ← parámetro

💡 Punto clave

Cada función tiene su propio entorno local. Los parámetros son simplemente variables que se agregan a ese entorno. Cuando la función termina, su entorno se descarta.

📞
Evaluador — Parte 3

¿Cómo funciona una llamada a función?

Cuando el evaluador encuentra suma(7, 8), ejecuta 5 pasos exactos. Veamos cada uno.

1

Evaluar la expresión función

Busca "suma" en el Environment → obtiene el objeto Function

2

Evaluar cada argumento

Evalúa 7 → Integer(7), evalúa 8 → Integer(8)

3

Crear nuevo Environment

Crea un entorno hijo del entorno donde la función fue definida (closure). El _outer apunta al entorno capturado.

4

Enlazar parámetros → argumentos

a ← Integer(7), b ← Integer(8). Cada parámetro se guarda en el nuevo Environment.

5

Evaluar el cuerpo de la función

Ejecuta return a + b; en el nuevo Environment → Integer(15)

🧠 El código del evaluador:

def _evaluate_call_expression(node, env): # ❶ Evaluar la función function = evaluate(node.function, env) # ❷ Evaluar los argumentos args = [] for arg in node.arguments: args.append(evaluate(arg, env)) # ❸ Crear entorno hijo del CLOSURE new_env = Environment(outer=function.env) # ❹ Enlazar parámetros con argumentos for param, arg in zip( function.parameters, args ): new_env.set(param.value, arg) # ❺ Evaluar el cuerpo result = evaluate(function.body, new_env) # Si retornó algo, desempaquetarlo if isinstance(result, ReturnValue): return result.value return result

💡 ¿Por qué closure?

El paso ❸ es crucial: el nuevo entorno NO es hijo del entorno donde se llama la función, sino del entorno donde se definió. Esto es lo que permite que las funciones "recuerden" las variables de su contexto original.

Evaluador — Parte 4

Recursión: factorial(3) paso a paso

📝 La función:

let factorial = function(n) { if (n == 0) { return 1; } return n * factorial(n - 1); }; print(factorial(3)); // 6

📚 Pila de Environments (Call Stack):

🌍 Global → factorial: Function, ...
↑ outer
📞 factorial(3) → n: Integer(3)
↑ outer
📞 factorial(2) → n: Integer(2)
↑ outer
📞 factorial(1) → n: Integer(1)
↑ outer
📞 factorial(0) → n: Integer(0) ← CASO BASE!

⚡ Ejecución (se "apilan" y luego "desapilan"):

→ factorial(3): n≠0, necesito 3 * factorial(2)... espero
→ factorial(2): n≠0, necesito 2 * factorial(1)... espero
→ factorial(1): n≠0, necesito 1 * factorial(0)... espero
→ factorial(0): n==0 → return 1 ✅ ¡CASO BASE!
── ahora los resultados "bajan" (desapilan) ──
← factorial(1): 1 * 1 = Integer(1)
← factorial(2): 2 * 1 = Integer(2)
← factorial(3): 3 * 2 = Integer(6) 🎉

🔑 ¿Por qué funciona?

Cada llamada crea su propio Environment con su propia n. Aunque todas usan el mismo nombre "n", son variables diferentes en entornos diferentes. Cuando factorial(0) retorna, su entorno se destruye, y volvemos al entorno de factorial(1), donde n sigue siendo 1.
